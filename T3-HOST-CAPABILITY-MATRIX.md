**Implemented** means a generated face and matching shipped implementation were located, not that this running composition mounts it or the phone currently calls it. ### Transport / nesting

Endpoint names below are Typert names (`session/updateQueue`, etc.), not invented REST routes. Gateway payload is exactly `{args:{...named wire parameters...}}`; endpoint must contain two nonempty slash-separated segments ([gateway:1460–1471][GW]). A method's parameter named `request` remains nested: `{args:{request:{sessionId:"…",…}}}`. By contrast terminal creation uses `{args:{agentId:"…",request:{id:"…",cols:80,rows:24}}}`; files use `{args:{workspaceFileScopeId:"session-…",path:".",range:{}}}`. Signals/cancellation are transport-owned, not JSON fields. Stream frames below are business values before carrier envelopes. Optional `?` denotes omittable; all `number` fields are schema numbers unless a stronger implementation bound is stated.

### Result detail types

`Job={id:string,kind:string,label:string,owner?:string,outputLimitBytes?:number,status:'failed'|'running'|'stopping'|'completed'|'killed',progress?:string,detail?:string,startedAt:number,finishedAt?:number,output:{total:number,earliest:number,spillPaths?:string[]}}` ([schema:15–30][J]).

Change summary `files` is `{path:string,display:string,added:number,deleted:number,binary?:true,oversized?:true}[]`; diff refusal `kind` is `'binary'|'oversized'`; text `hunks` is `{oldStart:number,oldLines:number,newStart:number,newLines:number,lines:string[]}[]` (unified-prefix strings, 3 context lines; coarse whole-file fallback on timeout). [Implementation:518–578,892–932][C].

Schedule history page is `{id:string,records:{prompt?:string,scheduledAt:string,deliveredAt:string,messageId:string}[],earlierRecordsUnavailable:boolean,earlierRecordsPruned:boolean,retention:{days:number,records:number},nextBefore?:string}` or `{id:string,code:'schedule_not_found'|'delivery_cursor_not_found'}` ([schema:116–135][SCH]).

### Schedule exact record/timing types

`Record` common fields: `{id:string,kind:…,title:string,prompt:string,scheduledAt:string}` plus discriminator-specific fields: `after → afterSeconds:number`; `at → none`; `every → everySeconds:number`; `daily → time:string,timeZone:string`; `weekly → time:string,timeZone:string,weekdays:number[]`; `cron → expression:string,timeZone:string`. Target is RFC3339 UTC. Titles trimmed/nonempty/max120, every interval at least one minute, weekdays ISO 1–7 unique.

`Timing = {kind:'at',at:string|{date:string,time:string,time_zone:string}} | {kind:'every',every_seconds:number} | {kind:'daily',daily:{time:string,time_zone:string}} | {kind:'weekly',weekly:{time:string,time_zone:string,weekdays:number[]}} | {kind:'cron',cron:{expression:string,time_zone:string}}`. `expected` is the complete previously read record, not just revision/id. Update refusal variants include `{id,updated:false,code:'schedule_not_found'|'schedule_ended'|'schedule_conflict'}` and `{code,message}` validation/subagent refusals. [Schema:140–340][SCH].

## QAReadOnly and workspace isolation requirements

1. **This audit performed no live QA.** Static availability does not authorize invoking endpoints. A `qaReadOnly` UI flag is not a security boundary unless checked at every bridge ingress (unary RPC, stream open/uplink, HTTP/media).
2. In isolated QA, allow only explicit fixture/session/workspace identifiers. Never accept a caller-supplied sessionId/agentId/workspaceFileScopeId as sufficient proof; resolve ownership against the selected allowed workspace. Validate nested `args.request` and direct args equally. Process-global workspace/control/catalog streams must be filtered or excluded before emitting baselines and later updates; snippets/job output/schedules can contain unrelated personal information.
3. **Files are not confined merely by Session scope.** [Implementation:419–426,479–485,589–608][FI] deliberately permits out-of-workspace regular-file reads/stat. Directory list does enforce resolved containment ([495–513,576–582][FI]). Bridge-side canonical target/root containment (including baseFile, ancestor symlinks, absolute paths and traversal) is needed for isolated QA; cap bytes/entries and restrict approved fixture roots. Final-component symlinks are refused for regular-file reads, but that is not full workspace isolation.
4. **Terminal is privileged user execution:** [create implementation:818–844][TI] explicitly bypasses Agent sandbox/approval restrictions. Deny create, attach uplink write/resize, rename, close and retention effects during read-only QA; even attaching resolves Agent and can take input ownership, so prefer fixtures over a live attach. Never emulate missing Files/git APIs by executing terminal commands under the read-only flag.
5. Deny prompt/cancel/fork/rename/updateQueue/selectModel/create/upload, all workspace mutations/mkdir/picker, settings/credential writes, job kill, schedule update/delete/create, native open/reveal and plugin install/execution during QAReadOnly. Cold read endpoints differ from Agent lookups: terminal/environment/shells and completion resolve live Agent and are not automatically side-effect-free.
6. Exclude account profile/balance/sign-in/sign-out/bonus reads, credential resolution, provider/model discovery, remote media fetches and model catalog calls unless separately authorized. “Read API” does not guarantee no network or personal-data access. Report only redacted schemas/status facts; never log values, authorize URLs or upload receipts.
7. Full parity should preserve visible controls with honest capability/error handling while implementing true bounded gaps. Do not fake success, silently remap repository fork to conversation fork, map snooze to archive, or claim a shipped endpoint absent merely because Swift lacks a call.

### Wiring scope limitation

Workspace static searches did not locate `phoneNativeGateway` / `remoteMux` identifiers in JS/TS; parent was asked for their exact source path. Their current allowlist, QAReadOnly enforcement, carrier format and byte/uplink support were **not verified**. The carrier requirements above follow current shipped schemas/implementation, not an asserted audit of that custom bridge. No Swift/JS project edits were made.
