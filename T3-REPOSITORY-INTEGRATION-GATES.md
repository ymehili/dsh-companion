## Required before activation / whole-port completion

1. **Ingress and runtime packaging.** Existing `/Users/ymehili/dsh-mobile/bridge.mjs` authorizes the device then injects the Mac browser-owner cookie. Do not call it restricted-principal forwarding or broaden it. New adapter requires explicit session/header authority and reviewed ingress. Runtime is an opt-in factory requiring an injected engine; a real reviewed composition/entrypoint, journal lifecycle, actual packaged Typert/resource-policy verification and deployment plan are still needed. Do not mount/restart automatically; user owns Mac restart/activation review.
2. **Git fetch/pull/push.** Native forms exist; engine currently refuses them pending a credential/transport policy. Implement a fixed-host credential-free GitHub remote policy, Mac-only credential broker, no raw command/remote strings from phone, no token in argv/log/response, no interactive prompts, no credential helper or repo-hook surprises, no force/discard. Pull must preserve working files (fast-forward only). Network and write actions remain explicit user gestures/confirmations; tests use dummy credentials/fake transport/local disposable fixtures only.
3. **PR non-merge writes.** Standalone GitHub module implements them; engine strict default disables them. Create/plain comment cannot offer GitHub atomic head CAS; contract explicitly allows honest captured-head preflight semantics. Reviews can bind commit_id; merge has actual server SHA-CAS. Add explicit reviewed policy/capabilities for these real operations, not a claim of impossible parity or fake success. Respect repository identity and pending durable ledger; ambiguous writes must not replay, including after restart.
4. **Scalable snapshots.** Current engine fingerprints ALL tracked/untracked content, rejects symlinks/submodules and bounds to 2,000 paths / 16 MiB aggregate / 4 MiB per file/command. This is conservative and may refuse ordinary large projects. Design efficient HEAD/index + authorized dirty/untracked content proofs with per-path ownership/preconditions (do not substitute unchanged M status for byte identity or accidentally authorize unlisted paths), streamed hashes and honest partial/unsupported states. Add larger real disposable-repo coverage before calling this full Git parity.
5. **Filesystem races / external writers.** Per-engine mutex is not an exclusive lease against other Git processes/Agents. Keep no-force behavior and Git lock refusal, strengthen path/descriptor/race fencing and report partial outcomes accurately. Never solve by stopping models/jobs or changing sandbox permissions on render.
6. **Operation outcomes.** Current native controller conservatively locks writes after any failed submission; current journal records pending before task validation, so definite preflight rejection can conservatively become uncertain on retry. Introduce explicit prepare/no-effect vs may-have-applied outcomes if making this friendlier; do not weaken no-replay guarantees. Native form drafts currently survive sheet closures only for the project screen lifetime, not app restart.
7. **Native polish/regressions.** PR list currently shows shortened SHA (head is CAS SHA); optional branch display ref can improve source fidelity without replacing SHA. Verify all Git/worktree/action/merge flows, PR pagination, unmounted/read-only/auth/conflict/error states, same-side line/range comments, repeated post-write refresh and no cross-project effects. No fake turn seq for Git comments. Migrate remaining legacy tests, inspect light/dark/Dynamic Type/keyboard states against pinned T3 source.
8. **Related remaining product work.** Multi-connection/project lifecycle and durable unsent/new-task drafts/retry payloads, complete editor/media/voice/files write/search, native account callback relay, schedule create, genuine inbox driver reorder/hold, and other inventory items remain active work. Native UI controls must follow actual capabilities; staging/source tests do not establish live deployment.
